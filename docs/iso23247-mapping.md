# Відповідність платформи еталонній моделі ISO 23247

## 1. Observable Manufacturing Element

Фізичним об'єктом є автоматична кавомашина.

Відповідно до ISO 23247 склад фізичного об'єкта розглядається
за категоріями Observable Manufacturing Element (OME).

| Категорія OME | Відповідник у системі |
|---|---|
| Обладнання | резервуар води, насос, бойлер, нагрівач, заварювальний блок, контролер, сенсори |
| Персонал | користувач кавомашини, оператор платформи, інженер з обслуговування |
| Матеріали | вода, кава / кавові зерна або мелена кава |
| Процес | очікування, нагрівання, приготування напою, обслуговування |
| Приміщення | окремо не моделюється, оскільки приміщення не впливає на функції цифрового двійника в межах роботи |
| Довкілля | температура та вологість приміщення окремо не моделюються, оскільки не входять до визначеного реєстру сигналів |
| Продукт | готовий кавовий напій |
| Документація | конфігурація обладнання, реєстр сигналів, правила діагностики, технічна документація |

Категорії «приміщення» та «довкілля» є частиною предметної області,
але їхній стан у поточній версії платформи не використовується
для синхронізації цифрового двійника.

## 3. Пояснення відповідності

### DCE: збирання даних

Фізична кавомашина або її емулятор формує значення сенсорів.
MQTT Publisher серіалізує телеметрію в JSON та публікує її
у відповідні MQTT topics.

Telemetry Consumer платформи отримує повідомлення через MQTT Broker.

### DCE: керування пристроями

Зворотний канал використовується для передачі команд:

- запуск приготування;
- зупинка приготування;
- зміна температурної уставки.

Команди передаються через окремі MQTT topics.

### DTE: застосунки та служби

Twin State Manager підтримує актуальний цифровий стан кавомашини.

Anomaly Analyzer аналізує телеметрію та визначає аномальні режими,
зокрема:

- Clog;
- HeaterFailure;
- PumpFailure.

### DTE: доступ до ресурсів та обмін

До цього рівня належать механізми взаємодії цифрового двійника
з іншими компонентами:

- MQTT Consumer;
- REST API;
- WebSocket API.

REST API використовується для запитів стану та історії,
а WebSocket — для оперативного push-оновлення інтерфейсу.

### DTE: функціонування та керування

Platform Management відповідає за:

- конфігурацію платформи;
- контроль доступності компонентів;
- моніторинг;
- ведення журналів;
- контроль стану підключень.

### User Entity

Користувач взаємодіє з платформою через Web UI.

Інтерфейс дозволяє:

- переглядати поточний стан;
- переглядати телеметрію;
- отримувати інформацію про аномалії;
- подавати дозволені команди керування.

## 4. Наскрізні служби

### Захищеність

Передбачаються:

- TLS для захисту мережевого каналу;
- автентифікація MQTT-клієнтів;
- MQTT Access Control Lists;
- авторизація команд керування;
- журналювання команд.

Зворотний канал керування розглядається як більш критичний
за канал телеметрії, оскільки команда може безпосередньо
впливати на фізичний об'єкт.

### Якість даних

Перед використанням телеметрії перевіряються:

- структура JSON;
- MachineId;
- SensorId;
- одиниця вимірювання;
- допустимість числового значення;
- timestamp;
- sequence number;
- за потреби діапазон значення.

Sequence number також використовується для виявлення
пропущених або дубльованих повідомлень.

### Взаємодійність

Для зменшення зв'язності між компонентами використовуються
стандартизовані інтерфейси:

- MQTT для подієвого обміну;
- JSON як формат повідомлень;
- HTTP/REST для запитів;
- WebSocket для push-оновлень.

Кожен сигнал має визначені:

- ідентифікатор;
- джерело;
- тип;
- одиницю;
- діапазон;
- частоту.

## 5. Покриття еталонної моделі

У межах архітектурного проєкту всі дев'ять застосовних сутностей
еталонної моделі мають відповідник.

Кількість застосовних сутностей:

nетал = 9

Кількість сутностей, для яких визначено архітектурний відповідник:

nвідп = 9

Покриття:

C = nвідп / nетал × 100 %

C = 9 / 9 × 100 % = 100 %

Отже, покриття застосовної частини еталонної моделі ISO 23247
становить 100 %.

Статус «закрито» в цій таблиці означає, що функцію передбачено
в архітектурі платформи. Повна програмна реалізація всіх механізмів
може виконуватися в наступних лабораторних роботах.
